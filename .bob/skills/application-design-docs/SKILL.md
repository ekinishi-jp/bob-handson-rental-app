# Application Design Docs

このSkillは、Webアプリケーション開発における設計書を作成・更新するために使用します。

対象は、ブラウザで利用する画面、バックエンドAPI、データストア、入力フォーム、検索、一覧、詳細、登録、認証・認可、テストを持つWebアプリです。特定の言語、フレームワーク、DB製品には固定せず、プロジェクトで採用済みの技術スタックに合わせて記述します。

## このSkillを使う場面

以下のような依頼を受けた場合に、このSkillを使用します。

- 既存Webアプリを解析して設計書を作成する
- 新機能の基本設計書を作成する
- 画面、API、DBをまたぐ変更の設計書を更新する
- 入力バリデーション、認可、個人情報保護、テスト観点を設計に反映する
- 設計変更の影響を複数の設計書へ反映する

## テンプレートファイル

このSkillでは、以下のテンプレートファイルを参照します。

| 設計書 | テンプレート | 用途 |
|---|---|---|
| 要件定義書 | `requirements_template.md` | 目的、利用者、ユーザーストーリー、機能要求、画面要求、API要求、データ要求、非機能要求、受入条件を整理する |
| 基本設計書 | `basic_design_template.md` | Webアプリの全体構成、画面設計、API設計、DB論理設計、データフロー、セキュリティ設計、テスト方針を整理する |
| 詳細設計書 | `detailed_design_template.md` | フロントエンド、バックエンド、DB、API処理、バリデーション、エラー処理、テスト実装に必要な詳細を整理する |

## 共通ルール

- テンプレートの章立てに準拠して作成します。
- テンプレートにない項目でも、設計上必要な場合は適宜追加します。
- 1つのファイルを一度に大量出力せず、章ごとに作成・更新します。
- 設計書には、実装コードそのものを過度に含めません。
- 必要な場合は、Mermaid図、表、簡易ワイヤーフレームを使用します。
- 画面、API、DBのどれかを変更する場合は、他の2つへの影響を必ず確認します。
- 画面からAPI、APIからDBまでのデータフローを追えるようにします。
- 入力フォームがある場合は、必須項目、入力形式、エラー表示、送信後の状態を明記します。
- 個人情報やユーザー別データを扱う場合は、認証・認可・水平権限不備の防止・ログ出力制御を明記します。
- テスト観点は、正常系、異常系、権限違い、バリデーション、画面表示、ビルド確認を含めます。

## 基本設計書テンプレート

ファイル: `basic_design_template.md`

基本設計書では、要件を実現するためのWebアプリ全体像を整理します。

主に以下を明確にします。

- システム構成
- 技術スタック
- 機能一覧
- 画面一覧
- 画面遷移
- API一覧
- DB論理設計
- データフロー
- セキュリティ設計
- テスト方針

## 出力時の注意

設計書を出力する場合は、ユーザーが指定した保存先にMarkdownファイルとして作成します。

既存の設計書がある場合は、新規作成ではなく既存ファイルを更新します。

ユーザーから出力先の指定がない場合は、プロジェクト内の文脈に合わせて `docs/` 配下または既存の設計書保存場所を提案します。
